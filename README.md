## Reflection:

**What is a commit?**

A commit is the act of creating a snapshot of the current state of the project. It saves the state of the project and allows any collaborators to see what you've worked on. (My wording for the second part might be overlapping a bit with how one would describe a pull request, but they're different in that a pull request aims to fold one branch into another, while a commit just updates the branch it's on.)

**Why might you use a branch instead of editing `main` directly?**

Using a branch allows you to test changes without affecting `main`. This is useful if you don't know whether the changes will work out, since it means you don't introduce those changes for others until you're sure they work.

**How does an issue differ from a pull request?**

A pull request proposes changes to the repository; an issue just flags something to be looked into without submitting any changes to the repository.
